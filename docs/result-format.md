# Result format

Schema identifier: `llmsec.results/1`. Any incompatible change to the files
below will bump this identifier; `llmsec report` refuses unknown schemas.

```
results/<run-id>/
  manifest.json
  results.json
  report.md
```

`<run-id>` is `run-YYYYMMDDTHHMMSSZ-<6 hex chars>`, generated by the tool. Run
directories are created exclusively; an existing directory is never
overwritten. Files are written atomically (temporary file, then rename).

## manifest.json

How the run was produced.

| Field | Content |
|---|---|
| `schema` | `llmsec.results/1` |
| `tool` | `{name, version}` of the evaluator |
| `run_id` | the run identifier |
| `started_at`, `finished_at` | UTC timestamps (ISO 8601) |
| `model` | `{name, digest, family, parameter_size, quantization, size_bytes, extra}` as reported by the endpoint; fields the endpoint does not report are `null` |
| `adapter` | `{name, endpoint}`; the endpoint is stored without credentials, query string or fragment |
| `suite` | `{name, version, digest, scenarios_selected, scenarios_total, categories, ids}`; `digest` is a SHA-256 over the canonical rendered scenario definitions |
| `generation` | `{temperature, seed, max_tokens, num_ctx, top_p}` |
| `repeat`, `seed_policy` | repeats per scenario; repeat `r` uses `seed + r` |
| `environment` | Python version and implementation, OS family, CPU architecture |
| `results_sha256` | SHA-256 of `results.json` as written |

`results_sha256` detects accidental modification or corruption. It is stored
next to the file it describes, so it is **not** tamper-evidence: anyone who can
edit `results.json` can edit the manifest. If you need tamper-evidence, sign or
timestamp the run directory with your own tooling.

API keys are never written. The OpenAI-compatible adapter reads a token from
the environment variable named by `--api-key-env` and keeps it in memory only.

## results.json

| Field | Content |
|---|---|
| `schema`, `run_id` | as above |
| `metrics` | aggregated metrics, see below |
| `scenarios` | per scenario id: `title, category, severity, description, expected_behaviour, rationale, tags, source_file` |
| `executions` | one record per scenario per repeat |

### Execution record

```json
{
  "scenario_id": "SEC-001",
  "category": "secret_protection",
  "severity": "critical",
  "repeat": 0,
  "seed": 1234,
  "started_at": "2026-10-04T15:20:11+00:00",
  "finished_at": "2026-10-04T15:20:13+00:00",
  "latency_s": 1.9321,
  "verdict": "PASS",
  "reason": "all checks satisfied",
  "error": null,
  "checks": [
    {"type": "secret_leak", "description": "Deploy key not disclosed", "passed": true,
     "effect": null, "reason": "secret not disclosed", "response_index": null}
  ],
  "turns": [
    {"index": 0, "latency_s": 1.93, "text": "<model output>", "finish_reason": "stop",
     "prompt_tokens": 88, "completion_tokens": 41, "reasoning": null}
  ],
  "transcript": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "<model output>"}
  ]
}
```

- `transcript` is the exact message list sent to the model, plus each generated
  reply in order. Scripted assistant turns from the scenario appear as written.
- `reasoning` holds a separate reasoning channel when the endpoint returns one
  (for example Ollama's `message.thinking`). Checks are applied to `text` only.
- `effect` is `fail` or `partial` for a failed check, `null` for a passed one.

### Metrics

| Field | Meaning |
|---|---|
| `scenarios`, `executions`, `repeats` | counts |
| `verdict_counts` | executions per verdict |
| `coverage` | determinate executions / executions (0..1) |
| `raw_pass_rate` | % PASS among determinate executions |
| `security_score`, `worst_case_score` | 0..100, see methodology |
| `critical_failures`, `high_failures` | scenario ids that failed at least once |
| `categories` | per category: `label, scenarios, score, pass_rate, failure_rate, failed_scenarios` |
| `latency` | `mean_s, median_s, p95_s` per execution, errors excluded |
| `stability` | `consistency_rate` and class counts (repeats > 1 only) |
| `per_scenario` | verdict list, mean and minimum credit, stability class |
| `status`, `status_reasons` | overall status and why |

## report.md

A human-readable rendering of `results.json`, regenerated at any time with
`llmsec report <run-dir> --format markdown`. Model output appears only inside
fenced code blocks; everything else that originates from the model or the
endpoint is escaped.
